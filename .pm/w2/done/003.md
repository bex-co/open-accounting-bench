# Evaluate keyed seed derivation for the Holdout track

Assess whether Holdout instances should derive seeds through a keyed
function (for example HMAC with an unpublished key), so that public
generators cannot reconstruct Holdout instances by enumerating seeds.

- Write up the threat model and a recommendation in
  `docs/governance.md#holdout-track` terms only — no Holdout families,
  seeds, or expectations here or in any public file.
- Reference practice: keyed generation identity in the open
  beancount-ledger environment.
- Pillar B1. Sub-hour evaluation.

---

**Resolved 2026-11-05** — threat model and recommendation written into `docs/governance.md#holdout-track`: unpublished seeds from a small range give no protection for public generators (enumeration regenerates instances and answers), so holdout seeds for public generators should be `HMAC-SHA256(key, family || index)` with an offline key, a published `SHA-256(key)` commitment, and per-release rotation. Verified that all 293 registered families generate deterministically from 256-bit seeds, so no generator change is needed. No holdout families, seeds, or expectations were written anywhere; shipped in the commit that moved this note.
