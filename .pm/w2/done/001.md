# Budget-stratified reporting in `oab report`

`oab report` already has `cost_usd` and token counts per trial. Add reward
by token/cost budget bin, and within each bin compare high- vs low-token
tasks. APEX-Accounting reports a Simpson's-paradox pattern: scores rise
with budget overall but, within a budget-constrained harness, fall on
tasks where the model spends more tokens.

- `src/oab/report.py`, `docs/metrics.md`, a `tests/test_report.py` case.
- Pillar B3. Sub-hour; keep as a note unless it grows.

---

**Resolved 2026-11-05** — `oab report` adds a "Reward by token budget" section: graded trials in terciles by tokens spent (input + output) with reward rate per tercile, worded as descriptive only (harder tasks draw more tokens; compare budgets by rerunning with a controlled budget); documented in docs/metrics.md and tested in tests/test_report.py; shipped in the commit that moved this note. The within-bin task comparison was left out: without a budget-constrained harness it only restates task difficulty.
